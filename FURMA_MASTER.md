## 1. Executive Summary

Furma.tech is a digital holding company and venture studio designed to build, scale, and automate digital products. To maintain development velocity across multiple products without context collapse or extreme server burn, Furma.tech operates on a strict **Dual-Vertical Strategy**:

1. **Standard B2B SaaS (The Cash Engine):** Isolated, high-value platforms for traditional industries (tourism, hospitality) to generate stable Monthly Recurring Revenue (MRR).
2. **Aitlas (The Agentic Ecosystem):** A cohesive suite of AI-native products built around the Model Context Protocol (MCP), asynchronous task execution, and autonomous AI agents.

## 5. Technical Architecture (The "Furma Core")

To keep AI coding assistants (Cursor, Copilot) from hallucinating (Context Collapse), Furma uses a **Standardized Polyrepo Strategy**.

### The Stack

| Layer | Technology | Purpose |
|-------|------------|---------|
| **Framework** | Next.js 16 (App Router) | UI + fast API routing |
| **Runtime** | Bun | Speed + long-running f.loop scripts |
| **Database** | PostgreSQL + pgvector + Prisma 6 | Relational + vector search |
| **UI/UX** | React 19 + Tailwind CSS v4 + shadcn/ui | Consistent design |
| **AI Protocol** | MCP (Model Context Protocol) | Inter-app tool communication |
| **Validation** | Zod | All inputs validated |
| **Logging** | Pino | Structured logging |
| **Rate Limiting** | Upstash Redis | API protection |
| **Encryption** | AES-256-GCM | BYOK key storage |

### The Rule: Standardized Polyrepo

| Principle | Implementation |
|-----------|----------------|
| **No Monorepos** | Every product = isolated repo |
| **furma-core-template** | All repos cloned from this base |
| **MCP Communication** | Products talk via strict MCP standards |
| **Shared Zod Schemas** | Published to private registry (@furma/schemas) |
| **AGENTS.md** | Every repo has AI coding guidelines |

### The Asynchronous Execution Loop

To bypass strict Vercel serverless timeouts (30-60s) for agentic tasks:

```
┌─────────────────┐
│  Next.js (UI)   │
│  Vercel/Edge    │
└────────┬────────┘
         │ 1. User prompt
         │ 2. Encrypt BYOK key (AES-256)
         │ 3. Write PENDING task
         │ 4. Return taskId immediately
         ▼
┌─────────────────┐
│   PostgreSQL    │
│   (Neon)        │
└────────┬────────┘
         │ 5. Poll for PENDING
         │ 6. Decrypt key in memory
         │ 7. Execute LLM/MCP logic
         │ 8. Update COMPLETED
         ▼
┌─────────────────┐
│  f.loop Worker  │
│  Railway/Render │
│  (Bun 24/7)     │
└─────────────────┘
```

## 6. Security & BYOK Data Model

Because Nexus handles user-provided API keys (OpenAI, Anthropic, DeepSeek), plain-text storage is strictly prohibited.

### Prisma Schema Blueprint

```prisma
model User {
  id            String    @id @default(cuid())
  email         String    @unique
  computeCredits Int      @default(0)
  apiKeys       ApiKey[]
  agents        UserAgent[]
}

// AES-256 Encrypted BYOK Storage
model ApiKey {
  id String @id @default(cuid())
  userId String
  provider String // "OPENAI", "ANTHROPIC", "DEEPSEEK"
  keyData String // Encrypted token
  iv String // Initialization Vector
  tag String // Authentication tag
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  
  @@unique([userId, provider])
}

// Dynamic Agent Store
model Agent {
  id String @id @default(cuid())
  name String // "The Crypto Quant"
  basePrompt String @db.Text
  isPremium Boolean @default(false)
  skills AgentSkill[]
}

model Skill {
  id String @id @default(cuid())
  name String
  fallbackLogic String @db.Text // Open-source fallback if f.xyz tool missing
  agents AgentSkill[]
}
```
